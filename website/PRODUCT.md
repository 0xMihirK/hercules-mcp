# Hercules

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Security practitioners evaluating an agent-driven Kali workspace, and developers connecting agents, workers, or custom STDIO MCP integrations.

## Product Purpose

Explain Hercules accurately and make its installation easy to find. Demonstrate how several tools produce evidence and reports inside a client-owned Docker runtime.

## Positioning

The host-side MCP server owns explicit runtime lifecycle, client sessions, selected capabilities, bounded tool output, and workspace evidence. One catalog controls both the advertised MCP surface and installed Kali binaries.

## Capabilities and Constraints

Windows, macOS, and Linux hosts with Docker and local STDIO MCP clients are supported. Docker contains powerful tooling; networking and privileges remain operator-controlled. The four showcased clients are examples, not the compatibility boundary.

Demonstrations use real native clients and real Hercules tools in disposable local labs. Model responses and reasoning are scripted. Personal accounts, credentials, paid model calls, and external target scans are excluded. Visitors receive static recordings and evidence files.

## Brand Commitments

Preserve the graphite/copper palette, Archivo and IBM Plex typefaces, Hercules wordmark, and procedural smoke/hatch Canvas background. Use concrete, direct copy and factual demonstrations.

## Evidence on Hand

The repository contains the tool catalog, lifecycle and ownership implementation, output filters, and canonical installation prompt. The showcase capture matrix contains 120 validated native sessions: four pinned clients, ten local investigations, and three terminal geometries. Each session records actual Hercules execution, verified report artifacts, an evidence index with checksums, and transaction-owned cleanup. Model responses remain scripted. Raw recording bytes and timestamps, tool validation journals, source/image configuration, and browser frame proofs establish provenance.

## Product Principles

- Show the actual mechanism and preserve native client presentation.
- Keep compact inline output distinct from complete raw evidence.
- Make portability and custom-agent compatibility explicit.
- Publish measured examples instead of invented performance claims.

## Accessibility & Inclusion

Support keyboard navigation, narrow phones, reduced motion, readable transcripts, and static fallbacks. Native terminal colors are retained; surrounding page controls follow the site's theme.
