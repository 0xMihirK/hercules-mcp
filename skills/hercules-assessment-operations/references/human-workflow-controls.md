# Human workflow social-engineering controls

Use this playbook only for the named boundary in an authorized target or isolated fixture. Confirm target, identities, impact limits, and stopping condition before active work. Read saved notes and artifacts first; start the container only when a Docker-backed operation is actually needed.

## Hercules route

`workspace_inspect` for written procedures and synthetic scripts; no contact tool is implied. Check the live MCP tool list and backend availability; raw shell and browser commands do not inherit structured target guarantees.

## Test sequence

1. Model a specific verification step such as payment change or help-desk reset. Run a consented tabletop with scripted synthetic identities, then compare the documented approval path with a failed adversarial request. Capture process gaps without exposing individual employees.
2. Positive control: Legitimate request obtains required independent approval.
3. Negative control: Unverified request is paused or rejected without disclosing sensitive data.

## Evidence and decision

Retain procedure version, decision points, synthetic transcript, and remediation owner. Record what was observed separately from inferred impact. A valid control establishes that the test path worked; a missing result without that control is inconclusive.

## Limits and cleanup

Real impersonation, calls, and messaging require explicit scope, participant consent, and organizational coordination. Remove only test-owned artifacts and processes through an approved path, verify the resulting state, retain evidence, and stop the Hercules container after coordinated work. Report cleanup uncertainty rather than claiming success.
