# Multi-stage assessment sequencing

Use this playbook only for the named boundary in an authorized target or isolated fixture. Confirm target, identities, impact limits, and stopping condition before active work. Read saved notes and artifacts first; start the container only when a Docker-backed operation is actually needed.

## Hercules route

`system_list_sessions`, `workspace_inspect`, and narrow discovery tools before any active step. Check the live MCP tool list and backend availability; raw shell and browser commands do not inherit structured target guarantees.

## Test sequence

1. Translate the engagement into assets, identities, prohibited techniques, stop conditions, and evidence goals. Build a dependency graph: passive facts before active checks, proof before escalation, and cleanup before closeout. Coordinate one active worker per target to avoid conflicting tests.
2. Positive control: A known in-scope control is reachable by the planned method.
3. Negative control: Out-of-scope or unowned asset never enters the active queue.

## Evidence and decision

Retain scope record, decision log, finding IDs, and cleanup confirmation. Record what was observed separately from inferred impact. A valid control establishes that the test path worked; a missing result without that control is inconclusive.

## Limits and cleanup

A successful tool call is not a completed phase; mark skipped and inconclusive checks explicitly. Remove only test-owned artifacts and processes through an approved path, verify the resulting state, retain evidence, and stop the Hercules container after coordinated work. Report cleanup uncertainty rather than claiming success.
